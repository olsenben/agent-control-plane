# CT104 Agent Worker Platform

CT104 runs RLM agent flows as RQ workers (`rlm-root`, `report`) on steelleg.

**RLM-first adapter integration:** [ct104-rlm-first-adapter-plan.md](ct104-rlm-first-adapter-plan.md)

## Workers

| Service | Queue | Role |
|---------|-------|------|
| worker-rlm-root | rlm-root | Session bootstrap, policy load, FakeRLMEngine / RLM |
| worker-report | report | final_report.md, inbox result, optional Gitea comment |

## Prerequisites

CT103 must be live first:

- API + Redis + `worker-state` running
- Gitea webhook → state reduction verified
- Redis exposed on host `:6379` (UFW allows Tailscale only)
- Tailscale ACL allows `tag:agent-worker` → `agentcontrol:6379`

## Provisioning (steelleg)

Suggested: LXC **CT104** on steelleg, static LAN IP (e.g. `192.168.4.63/22`), 4–8 vCPU, 16 GB RAM, 100+ GB disk.

1. Create LXC with nesting enabled (Docker inside).
2. Install Docker Engine + Compose plugin.
3. Install Tailscale; assign **`tag:agent-worker`**.
4. Create local mount points and **share agent-state** with CT103:

```bash
sudo mkdir -p /mnt/agent-runs /mnt/agent-cache /mnt/agent-state
```

`agent-runs` and `agent-cache` are local to CT104. `agent-state` must be the same tree as CT103 so `worker-report` inbox files reach `agentctl results ingest`.

**Storage setup (required before workers):** [agent-state-storage.md](agent-state-storage.md) — NFS on **goldenleg** + **steelleg** Proxmox hosts, `mp0` bind mounts into CT103/CT104. Do **not** run NFS inside either container.

5. Bootstrap and deploy:

```bash
sudo CT103_TAILSCALE_IP=<ct103-ts-ip> bash scripts/ct104-host-bootstrap.sh
sudo bash scripts/ct104-ufw.sh
cd /opt/ai-sdlc-lab/agent-control-plane
docker compose -f docker-compose.ct104.yml up -d --build
```

**CI deploy (after bootstrap):** merge to `main` runs `.gitea/workflows/deploy-ct104.yaml` (test → SSH from CT102 → HTTP(S) `git pull` with token → `docker-compose.ct104.yml` up). Secrets: `DEPLOY_CT104_*`, plus shared `DEPLOY_GIT_TOKEN` — see [gitea-secrets.md](gitea-secrets.md). Git never uses SSH :22 to Gitea.

## .env (CT104)

Use the CT104-only template (not `.env.example`, which is for CT103):

```bash
cp .env.ct104.example .env
# edit REDIS_URL, GITEA_AGENT_TOKEN, etc.
chmod 600 .env
docker compose -f docker-compose.ct104.yml up -d --build
```

Minimum edits:

```bash
REDIS_URL=redis://<CT103_TAILSCALE_IP>:6379/0
AGENT_RUNS_HOST_PATH=/mnt/agent-runs
AGENT_CACHE_HOST_PATH=/mnt/agent-cache
AGENT_STATE_HOST_PATH=/mnt/agent-state
MODEL_ROUTING_POLICY=fake
```

Do **not** put `GITEA_BOT_TOKEN`, `GITEA_WEBHOOK_SECRET`, or `GITEA_ALLOWED_REPOS` on CT104. Optional `GITEA_AGENT_TOKEN` on `worker-report` only (`write:issue` scope).

## Git clone (HTTP, no SSH :22)

`worker-rlm-root` clones target repos over LAN HTTP(S). Gitea API tokens (`GITEA_AGENT_TOKEN`) are **not** used for clone — git needs HTTP credentials.

One-time on CT104 (same pattern as deploy):

```bash
sudo GITEA_DEPLOY_TOKEN=<read-only-pat> \
  GITEA_GIT_USER=deploy \
  bash scripts/configure-deploy-git-https.sh
```

Creates `/home/deploy/.git-credentials`. `docker-compose.ct104.yml` mounts that file into `worker-rlm-root` (override with `GIT_CREDENTIALS_HOST_PATH` in `.env` if needed). PAT scope: **`read:repository`**.

Verify non-interactive clone after deploy:

```bash
docker compose -f docker-compose.ct104.yml exec worker-rlm-root \
  git clone --depth 1 --branch main \
  http://192.168.4.60:3000/ai-sdlc-lab/agent-control-plane.git /tmp/clone-test
```

## Verify

```bash
# From CT104 — Redis over Tailscale
redis-cli -h <CT103_TAILSCALE_IP> ping

# Worker connectivity
docker compose -f docker-compose.ct104.yml exec worker-rlm-root agentctl worker doctor

# End-to-end inspect (from CT103 after workers up)
docker compose exec control-plane agentctl queue enqueue-rlm-test
# Watch rlm-root logs on CT104; artifacts under /mnt/agent-runs/...
docker compose exec control-plane agentctl results ingest --inbox
```

Webhook path (production):

1. Comment `/agent inspect <task>` on an allowed repo issue.
2. CT103 webhook appends event and enqueues state reduction.
3. `worker-state` writes `verification_state.json` with `dispatch_recommended`.
4. Dispatcher enqueues `rlm-root` job.
5. CT104 `worker-rlm-root` runs FakeRLMEngine; `worker-report` writes inbox JSON.
6. CT103 `agentctl results ingest --inbox` (or scheduled) merges result.

## Inspect MVP

- `/agent inspect` dispatches from CT103 after state reduction
- FakeRLMEngine makes **no model API calls**
- Artifacts under `/mnt/agent-runs/{owner}/{repo}/runs/{run_id}/`
- Results ingested via `agentctl results ingest --inbox`

## Credential boundary

- `worker-rlm-root`: Redis, HTTP git credentials (read-only PAT via mounted `~/.git-credentials`), agent-runs write — no Gitea API token, no model keys in `.env` for comments
- `worker-report`: optional `GITEA_AGENT_TOKEN` for issue comments only (`write:issue`)
